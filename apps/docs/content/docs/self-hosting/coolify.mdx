This page is for the **Kode GT fork** (`gustavoteixeirah/crikket`, branch
`main`). Upstream image-based compose files keep pulling
`ghcr.io/redpangilinan/crikket-{server,web}:latest` and must not be used for
[crikket.kodegt.com](https://crikket.kodegt.com). Do not build images on the
Coolify VPS — the web image is OOM-killed there (exit 137).

Operational summary also lives in [FORK.md](https://github.com/gustavoteixeirah/crikket/blob/main/FORK.md).

## Resource type

In Coolify, create **Docker Compose** from Git (not Nixpacks, not a single
Dockerfile build pack).

| Field | Value |
| --- | --- |
| Repository | `gustavoteixeirah/crikket` |
| Branch | `main` |
| Base directory | `/` |
| Compose file | `docker-compose.coolify.yml` |
| Build pack | Docker Compose |

`docker-compose.coolify.yml` **pulls** (never builds) from
`ghcr.io/gustavoteixeirah/`:

- `crikket-server:${CRIKKET_IMAGE_TAG:-main}` (`server` and `migrate`)
- `crikket-web:${CRIKKET_IMAGE_TAG:-main}`
- `crikket-proxy:${CRIKKET_IMAGE_TAG:-main}` (`caddy:2.10-alpine` with
  `Caddyfile.coolify` copied to `/etc/caddy/Caddyfile`, listening on `:8080`)

GitHub Actions (`.github/workflows/images.yml`) builds those images on push
to `main`. Merge, wait for **Images** to go green, then redeploy in Coolify.
Optional pin: `CRIKKET_IMAGE_TAG=sha-<short sha>`.

GHCR packages may be created private. Prefer making `crikket-web`,
`crikket-server`, and `crikket-proxy` **Public** in GitHub package settings
(repo is public; images contain no secrets). Otherwise add GHCR credentials
in Coolify. See [FORK.md](https://github.com/gustavoteixeirah/crikket/blob/main/FORK.md).

The Caddyfile is baked into the proxy image because Coolify turns
single-file bind mounts into directories (`is_directory=true`), which
breaks Docker (`mount ... not a directory`). Do **not** add a Coolify
file storage entry for `Caddyfile.coolify`. If one already exists from an
older deploy, delete it.

The Images workflow bakes `https://crikket.kodegt.com` as web `NEXT_PUBLIC_*`
build args. The web image entrypoint still requires the three origin vars at
runtime (compose defaults them so an empty Coolify value does not crash-loop
web) and substitutes placeholders for optional keys.

Do not commit secret values. Coolify supplies them.

## Domains and ports

Assign the public FQDN on the **`proxy`** service, container port **8080**.
Coolify's proxy terminates TLS and forwards there. Do not publish host ports
in the compose file (no `ports:` mappings). Do not set `container_name`.

`web` uses `network_mode: service:server` and has no network identity. **Do
not assign a Coolify domain to `web` or `server`.**

`Caddyfile.coolify` routes:

| Path | Upstream |
| --- | --- |
| `/api/*`, `/rpc/*` | `server:3000` (Hono) |
| `/mcp`, `/mcp/*` | `server:3000` (Hono, unbuffered Streamable HTTP) |
| everything else | `server:3001` (Next.js in the server network namespace) |

Do not expose Postgres (`5432`) on the proxy.

## Postgres volume

The compose file bind-mounts the existing Coolify volume data directory:

`/var/lib/docker/volumes/rk2h1ywgegcu9qyq45m4evoz_crikket-pg/_data`

Coolify's compose transformer drops `external: true` and rewrites named
volumes, so a literal host path is required to keep Kode GT production data.

If you are **not** that Coolify project, change the host path (or switch to a
named volume). Leaving the Kode GT path on another host will fail or mount
empty data.

## Required environment names

### Web

- `NEXT_PUBLIC_SITE_URL`
- `NEXT_PUBLIC_APP_URL`
- `NEXT_PUBLIC_SERVER_URL`

Optional: `NEXT_PUBLIC_CRIKKET_KEY`,
`NEXT_PUBLIC_DEMO_URL`, `NEXT_PUBLIC_POSTHOG_KEY`, `NEXT_PUBLIC_POSTHOG_HOST`,
`VITE_APP_URL`, `VITE_SERVER_URL`.
`NEXT_PUBLIC_GOOGLE_AUTH_ENABLED` is unused at runtime (default `false`).
Google is enabled when **both** `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`
are set on the server; the web reads `GET /api/public-config`.

### Server / migrate

- `DATABASE_URL`
- `BETTER_AUTH_SECRET`
- `BETTER_AUTH_URL`
- `CORS_ORIGINS`
- `STORAGE_BUCKET`
- `STORAGE_ACCESS_KEY_ID`
- `STORAGE_SECRET_ACCESS_KEY`
- `STORAGE_REGION` or `STORAGE_ENDPOINT`

Optional: `ALLOWED_SIGNUP_DOMAINS`, `ALLOWED_SIGNUP_EMAILS`, `BETTER_AUTH_COOKIE_DOMAIN`,
`STORAGE_ADDRESSING_STYLE`, `STORAGE_PUBLIC_URL`, `ENABLE_PAYMENTS`,
`RESEND_API_KEY`, `RESEND_FROM_EMAIL` (both required to send mail),
`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` (both required to enable Google),
`POLAR_*`, `CAPTURE_SUBMIT_TOKEN_SECRET`,
`UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`, `TURNSTILE_SITE_KEY`,
`TURNSTILE_SECRET_KEY`, `WEBHOOK_ALLOW_PRIVATE_URLS`, `WEBHOOK_APP_BASE_URL`,
`ORG_SECRETS_ENCRYPTION_KEY` (32-byte base64; `openssl rand -base64 32`;
needed only to save an org OpenAI transcription key).

For MinIO, set `STORAGE_ENDPOINT` to the S3 API URL and
`STORAGE_ADDRESSING_STYLE=path`.

### Bundled Postgres

Only if you use the `postgres` service in this compose file (not Aurora):

- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_DB`
- `POSTGRES_HOST_AUTH_METHOD`

Then set `DATABASE_URL` to `postgresql://USER:PASSWORD@postgres:5432/DB`.

## Local build check

```bash
docker compose -f docker-compose.coolify.yml config
```

`config` does not need the production data directory to exist and does not
build images. `up` on a machine that is not Kode GT Coolify will fail or
mount empty data until you change the postgres host bind path.

Runtime `up` still needs the environment names above. Upstream
`docker-compose.yml` remains the image-pull self-host path.
